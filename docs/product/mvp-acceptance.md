# Learning Navigator MVP 验收标准

> 本文是验收规范，不是测试结果。每次验收必须记录实际命令、环境、数据版本、通过数、失败数、覆盖率和未覆盖风险；未执行的场景只能标记 `NOT_RUN`，不得写成通过。

## 1. 发布判定

### 1.1 严重级别

| 级别 | 定义 | 发布规则 |
| --- | --- | --- |
| `BLOCKER` | 核心闭环不可完成、数据越界/丢失、AI 绕过人工、图规则错误、隐私泄漏或导出不可恢复 | 任一失败即不得发布 MVP |
| `HIGH` | 关键页面/异常恢复/可访问性主路径不可用，结果会误导用户 | 原则上全部通过；例外必须有负责人、截止时间和不误导用户的禁用方案 |
| `MEDIUM` | 不阻断闭环但明显降低效率或理解 | 可带已知限制发布，必须登记 |
| `LOW` | 视觉、文案或便利性问题 | 可进入后续迭代 |

### 1.2 通用通过条件

- 场景的 Then 条件全部成立，并有 UI、API、数据库或导出文件等可复核证据。
- 失败时数据保持预期一致性，且用户看到可理解原因与恢复入口。
- 自动化测试通过不替代人工可用性、键盘、屏幕阅读器和隐私检查。
- 不删除失败测试、不用模拟数据掩盖未实现能力、不把未运行命令报告为通过。

## 2. 验收环境与固定数据

### 2.1 最低环境

- 全新 SQLite 数据库与已执行的正式 Alembic 迁移。
- AI 关闭配置一套；MockProvider 配置一套；可控的超时、错误 JSON 和引用冲突响应各一套。
- 桌面浏览器视口、窄屏移动视口、键盘-only 和至少一种屏幕阅读器环境。
- 可写导出目录、不可写目录和空间不足/写入失败的可控替身。

### 2.2 “Python 基础”地图

节点至少包括：变量、条件、循环、函数、列表、字典、文件读取、异常处理、模块、小型文件处理项目。Fixture 必须含：

- 多个根节点。
- 菱形依赖。
- 跨模块硬前置。
- 一个孤立但合法的节点。
- `CONTAINS`、`PREREQUISITE`、`RELATED` 至少各一条。
- `PREREQUISITE` 方向统一为“前置 → 被依赖”。

### 2.3 “微积分与反向传播”地图

最小依赖：

```text
基本求导 → 链式法则 → 反向传播
```

### 2.4 AI 审核批次

MockProvider 对“我想学习使用 PyTorch 完成图像分类”返回：

- 至少三个合法节点。
- 至少两条合法关系，其中一条 `PREREQUISITE`。
- 一个用户将拒绝的可选节点。
- 一条用户将修改方向或端点的前置建议。
- 来源、理由、置信度、模型和提示词版本。

## 3. 三领域边界验收

### BND-01 个人状态不修改地图（BLOCKER）

**Given** 两位用户引用同一 `KnowledgeMapVersion`，对节点“变量”均无状态
**When** 用户甲将自己的“变量”更新为掌握等级 3 并添加练习证据
**Then** 地图节点、节点版本和所有关系均无变更；用户乙状态仍为空；只新增/更新用户甲的 `LearnerState`、证据和审计。

### BND-02 路线不等于地图（BLOCKER）

**Given** 同一地图上存在“基础完整”和“项目优先”两个目标配置
**When** 系统为同一用户分别生成两条 `LearningPath`
**Then** 两条路线可以有不同排序或可选节点，但引用同一明确地图版本；地图中不新增“路线顺序边”，原节点/关系不变。

### BND-03 地图版本不静默改写路线（BLOCKER）

**Given** 当前路线引用地图 v1
**When** 编辑者发布改变硬前置关系的 v2
**Then** 原路线仍引用 v1 并标记 `STALE`；用户看到影响摘要；只有用户确认后候选路线才成为当前路线。

### BND-04 节点迁移不静默搬移状态（BLOCKER）

**Given** v2 提议合并两个已有个人状态的节点
**When** 地图版本发布
**Then** 两份原状态仍可追溯；系统要求逐项确认迁移/合并策略并写审计，不自动选择较高分数覆盖。

## 4. 端到端核心场景

### E2E-A 人工创建地图并缩短路线（BLOCKER）

**Given** AI 未配置，用户从空数据库开始
**When** 用户创建“Python 基础”知识空间，建立模块、节点和有效前置关系，发布 v1，选择“小型文件处理项目”为目标并生成路线
**Then** 路线包含所有未达标硬前置且拓扑顺序合法；每一步都有推荐理由、已/未满足前置、解锁项、地图与算法版本。

**And Given** 初始路线已保存
**When** 用户把“变量、条件、循环”更新为已达到目标最低等级
**Then** 系统重算后这三个节点不再属于待学集合，路线自动形成候选缩短结果；地图无变化，状态和路线修订各自可追溯。

### E2E-B 循环检测（BLOCKER）

**Given** 地图已有 `A → B` 和 `B → C` 两条硬前置
**When** 用户尝试添加 `C → A`
**Then** 系统原子拒绝该边，显示循环 `A → B → C → A` 及边方向；原两条边仍存在，地图版本未被错误发布。

### E2E-C AI 生成草稿和部分审核（BLOCKER）

**Given** MockProvider 返回 PyTorch 图像分类的合法结构化草稿
**When** 用户请求生成、拒绝一个节点、修改一条前置关系并接受其余建议
**Then** 在审核动作前正式地图零变化；审核后地图草稿只包含人工最终接受项；被拒节点及引用它的未修复关系不进入草稿；每项保留原始建议、最终值、来源、置信度、模型、提示词版本、审核人和时间；地图仍需人工发布。

### E2E-D 递归阻塞解释（BLOCKER）

**Given** `基本求导 → 链式法则 → 反向传播`，用户对三者掌握等级均为 0
**When** 用户选择“反向传播”为目标并查看首页或节点详情
**Then** 系统明确显示“反向传播被链式法则阻塞”“链式法则被基本求导阻塞”，列出当前/所需等级，并推荐 `AVAILABLE` 的基本求导。

### E2E-E 完全关闭 AI（BLOCKER）

**Given** 无模型密钥且 AI 总开关关闭
**When** 用户依次执行人工创建地图、编辑关系、创建目标、计算路线、记录状态、导出 JSON，再把 JSON 导入空数据库
**Then** 所有动作可完成；系统不产生 AI 网络请求、占位建议或密钥错误；导入后关键对象与引用一致。

## 5. 知识地图与图规则

### MAP-01 关系语义分离（BLOCKER）

**Given** 模块 M `CONTAINS` 节点 A，节点 B `PREREQUISITE` 节点 C
**When** 系统计算 C 的祖先和解锁状态
**Then** B 参与硬前置计算，M 与 A 的包含关系只影响大纲；两类边在 UI 有不同类型、方向和图例。

### MAP-02 六类关系可表达（HIGH）

**Given** 两个合法节点存在
**When** 编辑者分别创建 `CONTAINS`、`PREREQUISITE`、`RELATED`、`APPLIES_TO`、`EXTENDS`、`ALTERNATIVE_TO`
**Then** 每类关系按独立枚举保存和导出；只有 `PREREQUISITE` 影响硬解锁；界面不把所有关系压成父子树。

### MAP-03 跨模块前置（BLOCKER）

**Given** 节点 A 与 B 属于不同模块
**When** 创建合法的 `A → B` 硬前置
**Then** 系统允许保存并能在目标子图、关系表和阻塞解释中看到该边。

### MAP-04 重复边和缺失节点（BLOCKER）

**Given** `A → B` 已存在
**When** 用户再次创建同类型同方向边，或创建指向不存在节点的边
**Then** 系统分别返回重复/引用错误，不新增边，不产生半成品地图版本。

### MAP-05 孤立、多根和菱形图（HIGH）

**Given** Fixture 同时包含孤立节点、多个根和菱形依赖
**When** 用户浏览地图并对菱形终点生成路线
**Then** 浏览页能显示全部结构；路线包含菱形两支所需节点且不重复；孤立节点不导致合法图失败。

### MAP-06 归档节点重建图（BLOCKER）

**Given** 一个节点被当前路线和关系引用
**When** 编辑者在新地图版本中归档该节点
**Then** 旧版本和旧路线仍可追溯；新图算法不把归档节点当作可学习；受影响路线被标记并给出修复路径。

### MAP-07 版本发布与回滚（BLOCKER）

**Given** v1 已发布，v2 草稿包含人工和已审核 AI 变更
**When** 人工发布 v2 后再选择回滚 v1
**Then** 版本历史、差异、操作者和来源保留；回滚产生新可追溯版本/指针变更，不硬删除 v2；个人状态不被回滚。

## 6. 路线、阻塞与首页导航

### PATH-01 目标祖先减已掌握集合（BLOCKER）

**Given** 目标 T 有硬前置祖先 A、B、C，A 已达到要求，B/C 未达到
**When** 生成路线
**Then** 待学集合只含 B、C、T（以及用户明确添加的补充项）；A 被列为已满足依据而非待学节点。

### PATH-02 偏好不得绕过硬前置（BLOCKER）

**Given** A 是 B 的未满足硬前置
**When** 用户选择“最短可行”“项目优先”或人工把 B 拖到 A 前
**Then** 系统不产生以 B 为可执行首步的路线；人工非法顺序被阻止并解释 A 的要求。

### PATH-03 多个可学习候选可解释排序（HIGH）

**Given** 两个节点同时 `AVAILABLE`
**When** 系统选择一个作为下一步
**Then** 两者均可查看；主推荐说明拓扑层级、难度、掌握程度、必要性和路线偏好中的实际依据，不伪造新的依赖。

### PATH-04 所有目标已掌握（HIGH）

**Given** 目标和全部硬前置已达到目标等级
**When** 打开路线或首页
**Then** 系统显示目标完成及依据，不生成空白/重复学习路线，并提供归档、提高等级或新目标操作。

### PATH-05 无可行动节点（BLOCKER）

**Given** 目标未完成但没有合法 `AVAILABLE` 节点
**When** 系统重算
**Then** 明确区分环、缺失引用、归档入口、版本冲突或规则矛盾，并提供地图修复入口；不能只返回“暂无推荐”。

### HOME-01 首页五问（BLOCKER）

**Given** 当前目标有一个进行中节点、至少一个阻塞节点和一个完成后可解锁节点
**When** 用户打开首页
**Then** 首屏无需进入二级页面即可识别：当前在学什么、为什么要学、下一步、哪些内容被阻塞、完成当前节点解锁什么。

### HOME-02 首页非打卡导向（HIGH）

**Given** 用户有学习时长和连续多日记录
**When** 打开首页
**Then** 时长、连续天数和排名不占主行动或首屏最高视觉层级；导航五问仍居首。

## 7. 学习状态与证据

### STATE-01 状态分类（BLOCKER）

**Given** 分别构造已达标、进行中、前置满足、前置未满足、不在目标子图和需复习的节点
**When** 计算导航状态
**Then** 它们分别得到 `MASTERED`、`IN_PROGRESS`、`AVAILABLE`、`BLOCKED`、`NOT_RELEVANT`、`NEEDS_REVIEW`，且分类依据可查看。

### STATE-02 等级和分数分离（BLOCKER）

**Given** 用户有 `mastery_level=2` 和独立 `mastery_score`
**When** 一次练习只改变内部评分
**Then** 系统不把两字段合并或无规则同步；展示等级变化仅按有版本的透明阈值/人工确认执行。

### STATE-03 可选学习记录（HIGH）

**Given** 用户只填写一段笔记，不填写计时、自评或下一步
**When** 保存学习记录
**Then** 笔记成功保存并关联节点，未填字段保持空，不用伪造默认证据或阻止提交。

### STATE-04 AI 评价不自动升级（BLOCKER）

**Given** AI 返回高置信度“已掌握”评价
**When** 保存该评价
**Then** 它最多成为 `AI_EVALUATION` 候选证据；`mastery_level` 不自动提高，页面提供人工审核入口。

### STATE-05 人工覆盖可审计（BLOCKER）

**Given** 当前等级为 2 且有已有证据
**When** 用户人工覆盖为 4
**Then** 保存前值、后值、操作者、时间、原因（可选）和 `manually_overridden`；原证据不被删除；路线随后重算。

### STATE-06 `NEEDS_REVIEW` 透明规则（HIGH）

**Given** 节点达到复习规则配置的期限
**When** 状态计算运行
**Then** 节点标记 `NEEDS_REVIEW`，显示规则版本和触发时间；不声称用户已经遗忘，也不静默降低人工等级。

## 8. AI 建议与人工审核

### AI-01 AI 只写建议队列（BLOCKER）

**Given** Provider 返回完全合法的高置信度地图
**When** 生成请求成功但尚无人审核
**Then** 只创建 `AISuggestion(PENDING)`；正式节点、边和已发布地图版本数量不变。

### AI-02 严格结构校验（BLOCKER）

**Given** AI 响应分别包含未知字段、缺失临时 ID、无效枚举、越界置信度和指向不存在节点的边
**When** 系统解析响应
**Then** 响应被拒绝或冲突隔离，并返回精确字段路径；未知字段不被偷偷忽略；不能出现可直接接受的正式变更。

### AI-03 环形 AI 建议（BLOCKER）

**Given** AI 建议会使 `PREREQUISITE` 子图形成环
**When** 建议进入审核
**Then** 相关项标记 `CONFLICTED` 并显示循环链；修复并重新校验前接受动作不可用。

### AI-04 人工锁定字段（BLOCKER）

**Given** 节点标题已由人工修改并锁定，AI 建议覆盖该标题
**When** 审核者打开建议
**Then** 页面突出人工值和冲突，禁止批量低风险接受；只有人工明确编辑后接受才能生成草稿差异。

### AI-05 批量接受安全边界（BLOCKER）

**Given** 批次同时有描述补全、节点删除、节点合并和前置边建议
**When** 用户选择批量接受低风险项
**Then** 只有用户勾选且预览过的低风险描述项可进入确认；删除、合并、前置边和人工字段覆盖均被排除。

### AI-06 审核撤销（HIGH）

**Given** 人工已接受一项建议并加入地图草稿
**When** 人工选择撤销
**Then** 草稿回到撤销后的明确状态，建议标记 `REVERTED`；原建议、接受和撤销动作仍可查。

### AI-07 Provider 失败可恢复（HIGH）

**Given** Provider 超时、限流、认证失败或返回非 JSON
**When** 用户请求生成
**Then** 页面说明失败类型且不暴露密钥，保留输入，允许重试/转人工；正式地图和建议队列无伪造成功项。

## 9. 10 个核心页面验收

每个页面以下条目均为明确验收项；页面应同时具备适用的加载、空、成功、错误、过期/冲突状态。

| ID | 页面 | 主要验收项 | 级别 |
| --- | --- | --- | --- |
| UI-01 | 首页 / 当前导航 | 五问首屏可识别；有唯一主行动；无目标、完成、路线过期和计算错误均有恢复入口 | BLOCKER |
| UI-02 | 知识空间列表 | 能创建、搜索、打开、归档和启动导入；卡片区分发布版本、草稿和待审建议 | HIGH |
| UI-03 | 知识地图浏览页 | 大纲、图谱、关系表信息一致；目标子图默认；目录/前置/个人状态叠加层不混淆 | BLOCKER |
| UI-04 | 知识地图编辑页 | 节点与六类关系可编辑；循环/重复/版本冲突明确；未保存变更可撤销；发布需人工确认 | BLOCKER |
| UI-05 | 节点详情页 | 显示定义、位置、目标、为什么学、前置/后续/关联、资源、笔记、证据和我的状态 | HIGH |
| UI-06 | 目标与路线页 | 可设置目标等级与五种偏好；展示地图/算法版本和逐步理由；非法人工排序被拒绝 | BLOCKER |
| UI-07 | 学习工作台 | 可只保存部分字段；AI 评价不自动升级；提交后展示状态和下一步变化 | BLOCKER |
| UI-08 | AI 建议审核页 | 原始输出、逐项差异、来源/置信度可见；接受/拒绝/编辑后接受/安全批量/撤销可用且可审计 | BLOCKER |
| UI-09 | 学习记录页 | 可按目标/节点/证据筛选，查看状态前后值，纠错不抹除审计，空状态不诱导打卡 | HIGH |
| UI-10 | 设置与数据导出页 | AI 开关、发送确认、密钥遮蔽、范围导出、导入预览、归档/永久删除边界明确 | BLOCKER |

### UI-ALL 页面异常一致性（HIGH）

**Given** 任一核心页面的数据请求失败
**When** 页面呈现错误
**Then** 保留已安全加载的上下文，显示可理解原因、错误标识和至少一个恢复动作；不显示堆栈或永久空白页，未提交输入不被无提示清空。

## 10. 导入、导出与隐私

### DATA-01 完整 JSON 往返（BLOCKER）

**Given** 验收库包含两个地图版本、目标、路线、个人状态、学习记录、证据、AI 审核结果和审计摘要
**When** 用户完整导出并导入全新数据库
**Then** 稳定节点键、关系类型/方向、版本、路线引用、个人状态和审核结论一致；对象计数与清单相符；所有引用可解析。

### DATA-02 安全导出范围（BLOCKER）

**Given** 系统配置含 AI 密钥、内部日志和用户未选择的附件
**When** 用户导出不含附件的完整业务数据
**Then** 导出包不含密钥、令牌、内部缓存/日志或未选择附件；清单明确格式版本、应用版本、时间、计数和校验摘要。

### DATA-03 无效导入原子失败（BLOCKER）

**Given** 导入包有未知节点引用、重复边或环形前置之一
**When** 用户执行校验与导入
**Then** 页面定位到对象和字段，正式数据整批不变，用户可下载/复制错误报告并修复后重试。

### DATA-04 默认不覆盖（BLOCKER）

**Given** 导入包稳定键与现有空间冲突
**When** 用户未选择合并策略
**Then** 默认创建新空间/草稿或停止确认；不会覆盖现有地图、路线或个人状态。

### DATA-05 导出失败（HIGH）

**Given** 目标目录不可写或生成过程中发生序列化错误
**When** 用户导出
**Then** 页面指出阶段和可重试建议，不把半成品标为成功，原数据不变，临时文件按安全规则处理。

### PRIV-01 外部 AI 明示同意（BLOCKER）

**Given** 外部 Provider 已配置，用户目标、笔记和证据同时存在
**When** 用户只选择目标描述生成地图
**Then** 发送前预览只含所选目标；用户明确确认后才发请求；取消时零请求、零建议；未选笔记/证据不被隐式发送。

### PRIV-02 禁用 AI 后无后台请求（BLOCKER）

**Given** 用户关闭 AI
**When** 浏览首页、地图、路线、工作台和设置并等待常规后台刷新
**Then** 不发生 AI Provider 探测或内容上传；所有人工功能保持可用。

### PRIV-03 秘密与日志（BLOCKER）

**Given** AI 调用因认证错误失败
**When** 查看 UI 错误、应用日志、审计和导出
**Then** 完整密钥/令牌均不可见；敏感输入按配置最小化或脱敏。

### PRIV-04 永久删除确认（HIGH）

**Given** 用户选择永久清除自己的数据
**When** 进入确认流程
**Then** 页面列出范围、依赖影响、不可恢复后果和导出建议，并要求二次确认；取消后数据不变。

## 11. 可访问性验收

### A11Y-01 键盘核心闭环（BLOCKER）

**Given** 用户不使用鼠标
**When** 从首页创建/选择目标、浏览地图、打开节点、记录学习、审核一项 AI 建议并导出数据
**Then** 所有控件可聚焦和操作，焦点顺序符合视觉顺序，焦点可见，模态关闭后焦点返回触发点，无键盘陷阱。

### A11Y-02 图谱等价替代（BLOCKER）

**Given** 图谱画布不可用或用户使用屏幕阅读器
**When** 查看节点前置、后续、阻塞链并创建一条关系
**Then** 可通过大纲/关系表和表单完成同等任务，获得相同类型、方向、来源、状态和校验错误。

### A11Y-03 非颜色状态（HIGH）

**Given** 页面同时有六种节点状态和多类关系
**When** 使用灰度/高对比环境查看
**Then** 状态和关系仍能由文字、图标/形状、线型及可读图例区分，文本和控件对比达到 WCAG 2.2 AA。

### A11Y-04 缩放与窄屏（HIGH）

**Given** 页面缩放 200% 或使用窄屏
**When** 完成首页导航、节点学习、路线查看和数据导出
**Then** 关键内容不遮挡、不要求双向滚动完成表单，错误和主操作保持可达；完整拖拽编辑若不支持则提供表单路径。

### A11Y-05 错误与动态更新宣读（HIGH）

**Given** 表单校验失败或状态重算完成
**When** UI 更新
**Then** 错误与具体字段关联并进入错误摘要；“下一步已更新”等变化由适当 live region 宣布，不无故夺走焦点。

### A11Y-06 减少动态效果（HIGH）

**Given** 系统启用减少动态效果
**When** 打开图谱、差异和路线变化
**Then** 无自动播放、闪烁或非必要大幅动画；信息完整性不依赖动画。

## 12. 性能、完整性与错误恢复

### PERF-01 基线图计算（HIGH）

**Given** 本地标准数据集不超过 1,000 节点和 5,000 关系，且硬前置合法
**When** 重复执行目标子图、路线和阻塞计算并采集至少 30 次稳定样本
**Then** P95 小于 2 秒；报告硬件、数据规模、冷/热启动条件；超限时 UI 显示进度并可恢复。

### ERR-01 保存版本冲突（BLOCKER）

**Given** 用户基于 v1 编辑，而另一变更已形成新基线 v2
**When** 用户提交旧基线草稿
**Then** 系统阻止静默覆盖，展示 v1/用户变更/v2 差异，并提供重放、复制草稿或放弃。

### ERR-02 路线目标损坏（BLOCKER）

**Given** 目标节点引用在当前候选地图版本中不可解析
**When** 生成路线
**Then** 不创建虚假空路线；用户看到目标、地图版本和修复入口；现有路线与状态保持不变。

### ERR-03 状态并发冲突（HIGH）

**Given** 同一用户节点状态在表单打开后被另一会话更新
**When** 提交旧值
**Then** 系统显示服务器现值、待提交值和时间，要求明确合并/覆盖；任何覆盖均有审计。

### ERR-04 证据附件丢失（HIGH）

**Given** 一条学习证据引用的本地附件已不可读
**When** 打开记录或导出
**Then** 记录和其他数据仍可访问，附件标记缺失并可重新关联；系统不自动降低掌握等级。

## 13. 成功指标验收方法

| 指标 | 验收方法 | 通过目标 |
| --- | --- | --- |
| 核心闭环完成率 | 至少 10 名目标用户执行 E2E-A 的任务脚本，不提供步骤提示 | ≥ 80% 无协助完成 |
| 首次可行动时间 | 用“Python 基础”示例，从进入产品到看到有理由的下一步 | 中位数 ≤ 15 分钟 |
| 阻塞理解 | 让受测者阅读 E2E-D 页面并口述先学什么及原因 | ≥ 90% 正确；字段完整率 100% |
| 路线可追溯 | 查询全部验收路线和推荐条目 | 100% 含地图版本、算法版本、理由 |
| AI 人审完整性 | 对正式地图中的 AI 来源变更反查审核记录 | 100% 可追溯，未审写入为 0 |
| 数据往返 | 执行 DATA-01 并比较规范化导出 | 关键对象/引用 100% 一致 |
| 无 AI 闭环 | 执行 E2E-E 并记录网络请求 | 人工动作全通过，AI 请求为 0 |

用户研究必须记录参与者数量、任务、失败点和原始口径。MVP 指标通过不等同于学习效果已经被科学验证。
