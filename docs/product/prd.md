# Learning Navigator 通用框架构建与认知导航产品需求文档

> 状态：产品定义稿
> 适用范围：通用产品契约；`LEARN` 是第一等、默认且当前主要使用场景，`UNDERSTAND` 与 `DO` 是并列扩展
> 本文中的“必须”均为 MVP 发布门槛；详细可执行验收见 [mvp-acceptance.md](./mvp-acceptance.md)。

## 产品底层契约

Learning Navigator 不是课程生成器，而是一套通用的**框架构建与认知导航工具**。用户可以从一个目标或问题出发，运用第一性原理识别其中最基本的要素、关系、条件与限制，先拆解，再重构为一幅清晰、完整且可持续更新的认知地图。

产品交付的不是一组零散信息或一个看似确定的直接答案，而是帮助用户持续回答：

1. 这件事的整体结构是什么，边界在哪里？
2. 基本要素之间如何关联，哪些是硬依赖，哪些只是语义联系？
3. 我当前处于什么位置，已经具备什么？
4. 距离目标还缺什么，受哪些条件与限制影响？
5. 接下来有哪些可行路径，为什么推荐其中一步？

所有模板共享同一个产品闭环：

```text
目标或问题
→ 第一性原理拆解
→ 结构化框架
→ 用户定位与缺口诊断
→ 可解释路径
→ 证据与反馈
→ 更新框架、定位或路径
```

### 三种框架模板

| 模板 | 典型输入 | 主要输出 | “进展”的含义 |
| --- | --- | --- | --- |
| `LEARN` 学习导航 | “学会 Python 并能完成数据分析” | 知识结构、先修依赖、掌握缺口与学习路径 | 掌握状态和学习证据的变化 |
| `UNDERSTAND` 领域/事物全景 | “理解半导体行业”或“弄清一项复杂技术” | 边界、要素、角色、机制、关系、争议与未知项 | 已理解/待验证范围及认知缺口的变化 |
| `DO` 行动框架 | “完成一次产品发布”或“把某件事做成” | 成果、子目标、条件、限制、依赖、决策点与行动路径 | 目标状态、产出证据、阻塞和风险的变化 |

`LEARN` 不是过渡形态或兼容模式，而是完整、长期保留的第一等模板，也是当前产品默认入口。它必须保留知识点、前置知识、掌握等级、能力维度、复习安排、学习资源、学习记录和学习证据等完整语义。`UNDERSTAND` 与 `DO` 在同一底层框架上并列扩展，不能以“通用化”为由削弱学习产品能力。

`GoalIntent` 改变领域解释和确定性的显示基线，但不改变 canonical status、四维分数、证据、解锁或路线计算。产品不得把 `LEARN` 的“掌握等级”显示词强加给 `UNDERSTAND` 或 `DO`，也不得把三类目标都中性化成含义模糊的“推进”。界面必须根据目标 intent 自适应：学习目标说“学习、掌握、复习”，理解目标说“理解、查证、探索”，行动目标说“执行、产出、验收”。

### 两层语义模型

`GoalIntent`（`LEARN` / `UNDERSTAND` / `DO`）是稳定、确定性的语义基线；`LEARN` 仍是默认基线。每个目标可以拥有一个 `semantic_profile`：AI 按目标选择一套受控功能模板，并可为五类对象称谓和四维显示名生成更贴切的内容语义；Profile 只能作用于呈现层。

计算层是不可被 `semantic_profile` 改写的规范事实：

- 六个 canonical status 及其状态机；
- `concept_understanding`、`procedural_skill`、`application_skill`、`memory_strength` 四维分数、顺序、权重和聚合规则；
- 证据类型、证据效力与审计；
- 硬依赖、解锁/阻塞判定；
- 路线生成、排序、版本和推荐理由。

AI 只允许为当前目标提供以下封闭字段：

1. `template_id` 必须精确选择当前 `GoalIntent` 下的一套版本化受控模板。当前注册表只有：`LEARN_MASTERY_V1`、`LEARN_PRACTICE_V1`、`UNDERSTAND_FAMILIARITY_V1`、`UNDERSTAND_EVIDENCE_V1`、`DO_DELIVERY_V1`、`DO_READINESS_V1`。
2. `node_label`、`module_label`、`route_label`、`record_label`、`evidence_label` 五类对象称谓；这些词和四维显示名可以自由适配目标内容。
3. `status_labels` 是显式固定字段对象，必须恰好包含 `AVAILABLE`、`BLOCKED`、`MASTERED`、`IN_PROGRESS`、`NEEDS_REVIEW`、`NOT_RELEVANT`；六个规范化后的显示词必须互不相同，并与 `template_id` 注册的完整状态组逐槽精确匹配。
4. `action_labels` 是显式固定字段对象，只能且必须包含 `AVAILABLE`、`IN_PROGRESS`、`NEEDS_REVIEW` 三个键；整组值必须与同一 `template_id` 注册的动作组逐槽精确匹配。
5. `dimension_labels` 是显式固定字段对象，必须恰好包含 `concept_understanding`、`procedural_skill`、`application_skill`、`memory_strength`；只改显示名，不改 key、顺序或分数。
6. `progress_levels` 的 Strict Schema 包络仍为 3–6 项、首项 0、阈值严格递增且落入安全带，但 AI 不能在包络内自由写词或拼阈值。完整有序的 `{min_score, label}` 元组必须与同一 `template_id` 注册的 progress template 精确匹配；不得只选部分、交换中间等级、拼接两个模板或跨 intent 复用。

安全带依次为：三级 `0 / 30–55 / 70–100`；四级 `0 / 15–40 / 45–70 / 75–100`；五级 `0 / 10–30 / 35–55 / 55–80 / 80–100`；六级 `0 / 8–25 / 20–45 / 35–65 / 55–85 / 80–100`。这些只是注册模板的结构防线，不构成 AI 自定义模板的许可；当前六套注册模板只有四级或五级，因此自拟三级或六级序列同样无效。

设计原则是：**AI 选择语义族/完整模板，规则拥有功能语义**。状态、动作和进度不是三个可分别选择的 AI 文案区；`template_id`、整组状态、整组动作和完整有序进度必须共同精确命中服务端同一注册项。`never mastered`、`not—mastered`、`绝非已掌握`、`never start`、`Not learned`、`Do not start`、`No review` 均必须拒绝；阈值合法但中间等级倒序、改写或拼接，使用模板 A 的状态/动作配模板 B 的进度，以及 `DO` 使用 `LEARN` 模板，也必须拒绝。五类对象称谓和四维显示名仍可自由适配目标内容。

因此“自动适配”只发生在 AI 选择最贴近目标的完整语义族，以及生成对象称谓和四维显示名时；功能槽位始终由模板绑定到 canonical key，系统不从自然语言反推功能语义，所以否定、反向或近似文案无法把状态与动作倒置。

所有显示词先做 Unicode NFKC 归一化、首尾去空白和连续空白折叠，再以 `casefold` 结果与所选模板做逐槽精确等值比较及组内唯一校验；包含 Unicode `Cc`（控制字符）或 `Cf`（格式字符）的词直接拒绝。Progress template 的起点、所有中间等级和达成态都由注册表整体拥有，AI 无权单独改写。

`semantic_profile` 是可选展示元数据。AI 生成结果、已保存旧 draft 的读取以及 draft 激活时，只要 Profile 任一必需字段、固定对象、`template_id` 与 intent 不匹配、模板任一槽位不匹配、归一化或结构规则失败，就丢弃**整个 Profile**并回退该 `GoalIntent` baseline；有效的核心地图、目标、路线草稿和激活流程不得因此失败。直接提交新 Profile 的写接口仍可返回校验错误。未知字段必须拒绝，AI 不得自造第七种状态、改写 canonical key、改变算法或把显示等级当作真实状态。

示例：

| 目标 | intent baseline | 内容自适应 `semantic_profile` 示例 |
| --- | --- | --- |
| 学习线性代数 | `LEARN`（默认） | 选择 `LEARN_MASTERY_V1`；“知识点 / 学习模块 / 学习路径 / 学习记录 / 掌握证据”可按内容适配；受控动作 `AVAILABLE=开始学习`、`IN_PROGRESS=继续学习`、`NEEDS_REVIEW=开始复习`；受控五级 `[0] 尚未掌握 → [20] 开始理解 → [45] 基本掌握 → [70] 能够应用 → [90] 熟练迁移` |
| 了解半导体行业 | `UNDERSTAND` | 选择 `UNDERSTAND_FAMILIARITY_V1`；“关键问题 / 认知模块 / 认知路径 / 探索记录 / 判断依据”可按内容适配；受控动作 `AVAILABLE=开始了解`、`IN_PROGRESS=继续了解`、`NEEDS_REVIEW=重新核验`；受控四级 `[0] 不知道 → [25] 听说过 → [55] 了解 → [85] 非常了解` |

两个示例仍使用同一套 canonical status、四维分数、证据、解锁和路线计算；变化仅发生在目标级显示语义。

### 明确边界

- 不是通用任务管理器：可以生成达成目标所需的行动框架，但不以日历、提醒、人员排班或待办吞吐为产品核心。
- 不是纯脑图：层级只是关系之一；地图必须能表达硬依赖、条件、限制、证据和多种语义关系。
- 不是直接答案生成器：可以给出阶段性结论，但必须同时呈现结论位于什么框架、依据什么、缺少什么以及如何更新。
- 不是自动课程生成器：`LEARN` 是完整的学习导航产品，但不会把 AI 批量生成课程内容、课时和讲义当成核心交付。

## 产品原则与领域边界

系统必须把“共享框架、目标路径、用户定位”分开管理。`KnowledgeMap`、`LearningPath`、`LearnerState` 是 `LEARN` 的正式产品能力和领域语义；其中需要兼容的是当前数据库字段、API 路径和旧 Schema 的具体命名，而不是学习能力本身。`UNDERSTAND` 与 `DO` 通过 intent-aware 的产品模型和视图扩展这些边界，不能把学习语义从产品主层移除，也不能强迫另外两类目标使用学习措辞。

系统必须始终区分以下三个领域：

| 领域 | 回答的问题 | 归属与生命周期 | 可以引用 | 明确禁止 |
| --- | --- | --- | --- | --- |
| 共享框架（`LEARN`：`KnowledgeMap`） | 目标/问题由哪些要素构成；学习时明确为知识点、技能与前置知识 | 属于框架空间，不属于某个用户状态；以版本形式持续更新 | 节点、硬依赖/前置知识、包含、关联、应用、扩展、替代、条件、限制和来源 | 保存个人进展；把个性化路径写回共享框架；用父子树代替全部语义关系 |
| 目标路径（`LEARN`：`LearningPath`） | 为当前目标，用户可以沿哪些学习步骤、探索分支或行动方向前进？ | 属于一个目标和一个用户；基于明确的框架版本生成，可重算且保留来源 | 框架节点、路径偏好、生成算法版本、推荐理由 | 充当框架；删除或改写框架节点；绕过硬依赖、条件或限制 |
| 用户定位（`LEARN`：`LearnerState`） | 用户相对框架处于什么位置；学习时回答掌握到什么程度、能力表现如何、何时复习 | 属于“用户 × 稳定节点”；独立于框架版本和路径 | 模板特定状态、掌握等级、能力维度、置信度、证据、复习时间、人工覆盖记录 | 修改共享节点或关系；把 AI 判断直接当成事实；因换路径而丢失历史 |

依赖方向只能是单向引用：`LearningPath` 和 `LearnerState` 可以引用 `KnowledgeMap` 中的稳定节点标识；它们不能反向改变地图。地图发布新版本后，现有路线保持可追溯，重新生成或迁移必须由用户明确确认。`LearnerState` 只有在节点被明确合并、替换或归档时，才通过可审计迁移处理，绝不静默搬移。

AI 是结构化草稿的生产者，不是真相来源。任何 AI 结果必须符合模板对应的结构契约，先写入 `AISuggestion` 建议队列，展示模型、提示词版本、来源、理由、置信度、不确定项和结构化原始输出，并经过 Pydantic 严格校验。正式地图仅能因人工“接受”“修改后接受”而改变；拒绝、批量处理、撤销和版本回滚均须留审计记录。AI 不得静默覆盖人工内容、直接删除内容、把推测冒充事实、直接提升用户状态或在未配置模型时阻断人工流程。

只有参与可达性、先后约束或解锁计算的**硬依赖边**必须保持 DAG。`CONTAINS`、关联、因果、对比、应用、角色协作、条件引用等其他关系可形成网络甚至闭环，但必须具有明确类型、方向（如适用）、来源和解释；系统不能为了满足 DAG 而把所有关系压扁为树。

## 1. 产品问题定义

人面对陌生、复杂或信息分散的事物时，通常不缺材料，缺的是把零散信息组织成整体认知的能力：

1. 目标或问题的真正边界是什么？
2. 最基本的要素、关系、条件与限制是什么？
3. 自己当前位于框架的什么位置？
4. 已经知道、具备或完成什么，还缺什么？
5. 现在可以理解、验证、学习或执行哪些节点？
6. 某个节点为何被阻塞，缺少的是依赖、证据还是条件？
7. 下一步可以向哪里深入或行动，推荐依据是什么？
8. AI 生成的框架如何被人工检查、修改、拒绝和版本化？

现有课程列表往往把内容顺序当成知识依赖，思维导图往往只有树形层级，笔记软件缺少可计算的关系，问答产品倾向于给出脱离结构的答案，任务软件则记录事项而不帮助建立问题模型。产品要验证的价值是：用户能从一个目标或问题建立可编辑、可审查的整体框架，定位自己与缺口，得到有依据的下一步，并在新证据出现后持续更新。

核心闭环：

```text
提出目标或问题并选择 LEARN / UNDERSTAND / DO
→ 澄清成功标准、范围与限制
→ 人工创建或请求 AI 生成结构化框架草稿
→ 人工审核要素、关系、条件、限制和不确定项
→ 定位当前位置与缺口
→ 生成可解释路径
→ 学习、探索、验证或执行并记录证据
→ 更新用户定位及必要的框架版本
→ 重算可行、阻塞和下一步
```

## 2. 非目标

MVP 不建设以下能力：

- 社区、关注、评论、排行榜、连续打卡、游戏货币或商城。
- AI 数字人、视频生成、自动课程生产或内容版权托管。
- 多机构、多租户、班级管理、教师排课或企业 LMS 能力。
- 以学习时长、活跃天数替代学习目标进展。
- 声称掌握评分已经过认知科学或学习效果验证。
- 复杂推荐模型、黑箱机器学习、自动绕过硬性前置。
- 第一阶段 PDF/Office 文档解析、复杂网页抓取或外部内容同步。
- Neo4j、微服务、消息队列、Redis 或大规模协作编辑。
- 自动发布 AI 生成结果或自动根据 AI 评价提升掌握等级。
- 用聊天答案替代框架、定位、路径和证据；或把 AI 生成的大纲直接当成可信地图。
- 演变成通用待办/项目管理器、纯脑图编辑器或自动课程生成与分发系统。

## 3. 用户角色

MVP 可由同一位用户同时承担多个角色，但权限动作必须保持语义清晰。

| 角色 | 主要目标 | 关键权限 |
| --- | --- | --- |
| 框架使用者 | 提出目标/问题、查看下一步、学习/探索/执行、记录证据、更新自己的定位 | 查看已发布地图；创建目标和路径；编辑自己的笔记、证据和状态；导出自己的数据 |
| 地图编辑者 | 独立维护准确、可解释且必要时可计算的框架 | 创建/编辑/归档节点、关系、条件与限制；创建地图草稿；提交或发布新版本；不得修改他人个人状态 |
| AI 建议审核者 | 核对 AI 来源、差异和结构风险 | 接受、拒绝、修改后接受、批量处理低风险建议、撤销审核；发布前确认 DAG 与引用完整性 |
| 系统所有者 | 管理本地配置、AI Provider、备份和导出 | 配置 Provider 和隐私选项；查看本地审计；执行完整导出/导入；不能绕过审核门槛 |

MVP 默认单本地账户，不以复杂 RBAC 为前置；但所有写操作仍记录“执行者类型、动作、时间、对象、前后差异”，以便未来拆分角色。

## 4. 核心使用场景

### 4.1 从目标或问题开始

用户输入“使用 PyTorch 完成图像分类”。系统根据学习意图默认进入 `LEARN`，保留用户改选 `UNDERSTAND` 或 `DO` 的入口；随后复用已有地图或创建新空间。系统引导用户澄清学习成果、范围、条件和限制，人工搭建或让 AI 生成结构化草稿，经审核后诊断知识掌握与能力缺口，生成学习路径并解释首个推荐。

### 4.2 手工维护可信地图

地图编辑者创建模块、原子知识节点和语义关系。`CONTAINS` 仅形成目录，`PREREQUISITE` 采用“前置节点 → 被依赖节点”方向并保持 DAG。提交循环、重复边或不存在节点时，系统拒绝并说明修复方法。

### 4.3 审核 AI 框架

AI 生成的节点、边、合并建议和不确定项进入待审核队列。审核者查看原始输出、来源和逐项差异，拒绝一个节点、修改一条前置关系，再接受其余建议。只有这些明确接受的项进入新的地图草稿版本。

### 4.4 理解阻塞并前进

用户以“反向传播”为目标，而“基本求导”“链式法则”尚未掌握。系统展示完整阻塞链、每个前置的当前状态和最低要求，并推荐先学习“基本求导”，而不是只显示“未解锁”。

### 4.5 记录证据并重算路线

用户完成某节点后记录笔记、练习结果或项目产物，并人工更新状态。系统保留证据和审计记录，按透明规则重新计算 `AVAILABLE`、`BLOCKED`、`NEEDS_REVIEW` 以及下一步，原路线修订可追溯。

### 4.6 完全关闭 AI

用户未配置任何模型密钥或主动禁用 AI，仍可人工创建地图、编辑关系、创建目标、计算路线、记录状态并导入导出 JSON。AI 页面提供关闭原因和人工入口，不显示伪造建议。

### 4.7 理解一个陌生领域

用户以 `UNDERSTAND` 模板提出“我想建立对半导体行业的全景认识”。系统不是直接生成一篇行业介绍，而是先明确范围和视角，再组织价值链、关键角色、技术与商业机制、约束、争议、证据来源和未知项。用户可以定位已经理解和待验证的部分，并选择下一条探索路径。

### 4.8 完成一件复杂事项

用户以 `DO` 模板提出“把一个桌面软件发布给首批用户”。系统构建成果定义、子目标、硬依赖、必要条件、限制、风险、决策点和验收证据，指出当前位置和阻塞，形成行动路径。它不替代待办工具，而负责说明为什么需要这些行动、它们如何构成目标以及何时应更新框架。

## 6. MVP 功能

本节描述第一等且默认的 `LEARN` 模板实现范围。其知识点、前置知识、掌握、复习、能力维度和学习记录属于正式产品能力；`UNDERSTAND` 和 `DO` 可以延后实现，但新增能力必须复用“框架、定位、路径、证据、更新”的领域边界，不能复制出三套彼此不兼容的数据模型。

### 6.1 知识空间与地图

- 创建、重命名、归档知识空间；查看当前地图版本与版本历史。
- 创建、编辑、归档节点；支持稳定节点标识和节点来源。
- 创建、编辑、归档六类关系：`CONTAINS`、`PREREQUISITE`、`RELATED`、`APPLIES_TO`、`EXTENDS`、`ALTERNATIVE_TO`。
- 对 `PREREQUISITE` 做方向校验、重复边校验、节点存在性校验和 DAG 循环校验；对 `CONTAINS` 与 `PREREQUISITE` 使用不同视觉与交互。
- 大纲视图和目标子图视图；搜索、节点类型和个人状态筛选；深层图默认聚焦当前目标子图。
- 所有删除默认软删除或新版本变更，已发布版本可查看、比较和回滚。

### 6.2 目标、诊断和路线

- 创建学习目标：目标节点、目标掌握等级、路线偏好、可选截止日期、每日/每周负荷偏好。
- 路线偏好：基础完整、最短可行、项目优先、理论优先、人工自定义；任何偏好都不能绕过硬性前置。
- 计算目标节点全部硬性前置祖先，排除达到要求的已掌握节点，生成带算法版本的拓扑可行路线。
- 每个推荐返回推荐节点、推荐理由、已满足前置、未满足前置、完成后可解锁节点。
- 路线基于明确地图版本；地图更新时只提示影响和重算选项，不自动重写当前路线。

### 6.3 个人学习状态

- 按“用户 × 节点”保存 `mastery_level`、`mastery_score`、`confidence`、最近学习时间、下次复习时间、来源和人工覆盖标记。
- `LEARN` baseline 的掌握等级 0–5 显示为：未接触、能识别概念、能跟随完成、能独立完成、能解释并迁移、长期稳定掌握。目标级 3–6 个进度词只是四维分数的显示投影，不回写或重定义 `mastery_level`。
- 四维稳定键依次为 `concept_understanding`（概念理解）、`procedural_skill`（操作/计算能力）、`application_skill`（应用与迁移）、`memory_strength`（记忆保持）；显示名可由目标级 Profile 调整，但 key、分数和计算规则不可变。总掌握等级是摘要，不能抹平各维度强弱。
- 计算并展示 `MASTERED`、`IN_PROGRESS`、`AVAILABLE`、`BLOCKED`、`NOT_RELEVANT`、`NEEDS_REVIEW`。
- 学习记录可选字段包括起止时间、资源、笔记、困难点、自评、证据和下一步计划；不强制填满。
- 第一版使用透明、版本化规则：自评主要影响置信度；练习结果影响内部评分；人工审核证据才可明确提高展示等级；过期复习可标记 `NEEDS_REVIEW`。AI 评价只能作为证据候选，不能直接升级状态。

### 6.4 AI 建议与人工审核

- 输入支持自然语言目标、粘贴大纲、Markdown、纯文本和 JSON 节点数据；不支持 PDF/复杂文档。
- 生成知识空间边界、模块、原子节点、前置/关联建议、同义合并建议、警告和不确定项。
- 所有响应先严格结构校验，再保存到 `AISuggestion`；关系引用缺失节点或形成循环时进入冲突，不得应用。
- 展示原始建议、当前正式值、建议值、来源、理由、置信度、模型与提示词版本。
- 支持逐项接受、拒绝、修改后接受、撤销；批量接受只适用于用户明确勾选且已展示差异的低风险项。新增/删除节点、`PREREQUISITE`、合并及覆盖人工字段永远不属于低风险批量项。
- 接受建议产生新的地图草稿/版本和审计记录；AI 从不直写已发布地图。

### 6.5 导入、导出与无 AI 模式

- 导入 JSON 前进行版本、结构、引用、重复边和 DAG 校验；失败时整批不落正式数据，并返回定位到项的错误。
- 导出覆盖地图版本、节点/关系、目标、路线、个人状态、学习记录、证据、资源引用、AI 审核结论和审计元数据。
- AI Provider 缺失、停用或失败时，所有非 AI 功能保持可用。

## 7. 后续功能

只有在 MVP 闭环得到真实使用验证后才评估：

- PDF、Office 文档和网页材料的可追溯导入。
- 多用户协作、细粒度 RBAC、地图提案和多人审核。
- PostgreSQL、大图增量计算、性能证据充分后的图数据库评估。
- 间隔复习策略、更多评测类型，以及经验证的掌握模型。
- 路线方案比较、可选节点成本估算和跨知识空间引用。
- 面向教师/团队的共享模板，但不将其直接扩展成 LMS。
- 经用户选择的匿名产品指标和学习效果研究。

社区、排行榜、游戏经济和 AI 数字人不在已承诺路线图中。

## 8. 页面信息架构

MVP 包含附件所列的全部 10 个核心页面；详细区域与状态见 [information-architecture.md](./information-architecture.md)。

| 页面 | 首要任务 | 核心信息/操作 |
| --- | --- | --- |
| 首页 / 下一步 | 回答“现在关注/做什么，为什么” | 当前目标与节点、推荐下一步及理由、缺口/阻塞、完成后影响、最近证据、路径概览 |
| 地图空间列表 | 进入或创建一个领域/事项框架 | 空间名称、模板、地图版本、节点数、更新时间、目标数；新建、归档、导入 |
| 认知地图浏览页 | 理解目标相关整体结构 | 大纲/图谱切换、目标子图、搜索筛选、节点状态、关系图例、条件与限制 |
| 认知地图编辑页 | 人工维护可信地图 | 节点和关系编辑、硬依赖 DAG 校验、来源、未保存变更、提交新版本 |
| 节点详情页 | 理解一个节点及其目标作用 | 定义、为什么关注、依赖/后续/关联、条件、限制、证据、个人状态 |
| 目标与路径页 | 创建目标并解释路径 | 模板、目标结果、路径偏好、地图版本、缺口集合、顺序、分支、重算与影响 |
| intent-specific 工作台（默认学习工作台） | 按目标完成学习/探索/行动循环 | `LEARN` 显示知识点、前置知识、练习、掌握、能力维度、复习和学习记录；其他 intent 显示对应语义 |
| AI 建议审核页 | 人工控制 AI 变更 | 原始输出、逐项差异、来源/置信度、接受/拒绝/编辑后接受、冲突、撤销 |
| 进展页 | 回看路径、证据和状态变化 | 时间线、按目标/节点/证据筛选、记录详情、状态变更、人工覆盖与审计 |
| 设置与数据导出页 | 配置隐私和数据可携带性 | AI 开关与 Provider、发送前确认、导出范围、导入校验、备份、删除数据 |

全局主导航固定为“下一步、地图、进展、+ 新目标”。“+ 新目标”启动模板选择和目标澄清；目标与路径、编辑和 AI 审核作为上下文任务进入，避免把管理入口压过用户的认知与行动导航。

## 9. 关键状态定义

### 9.1 地图和版本状态

| 状态 | 定义 | 允许动作 |
| --- | --- | --- |
| `DRAFT` | 人工编辑中的版本，不供路线默认引用 | 编辑、校验、提交审核、删除未发布草稿 |
| `IN_REVIEW` | 等待人工最终确认 | 比较、修正、批准或退回；AI 无权批准 |
| `PUBLISHED` | 可供目标和路线选择的只读版本 | 基于它创建路线；由新版本取代但不原地改写 |
| `SUPERSEDED` | 已被新发布版本取代，仍供历史路线追溯 | 查看、比较、显式迁移路线 |
| `ARCHIVED` | 不再用于新目标 | 查看和导出；不得硬删除历史引用 |

### 9.2 节点导航状态

| 状态 | 判定含义 |
| --- | --- |
| `MASTERED` | 对当前目标要求已达到最低掌握等级 |
| `IN_PROGRESS` | 已开始学习但尚未达到目标要求 |
| `AVAILABLE` | 属于当前目标子图、所有硬前置达标、节点未归档且尚未达目标等级 |
| `BLOCKED` | 属于目标子图但至少一个硬前置未达标；必须附带阻塞链和推荐先修节点 |
| `NOT_RELEVANT` | 不属于当前目标祖先子图，也非人工加入路线 |
| `NEEDS_REVIEW` | 曾达到要求，但依据版本化复习规则需要复核；不能伪装为确定遗忘 |

以上六个 key 是 canonical status，跨 intent 保持不变。`semantic_profile` 只能通过当前 intent 的受控整包模板选择对应显示词，不得自由改写、增删、合并、重排或跨模板混用，显示词也不得参与分类计算。

### 9.3 AI 建议状态

| 状态 | 定义 |
| --- | --- |
| `PENDING` | 已校验并等待人工决定，未影响正式地图 |
| `CONFLICTED` | 引用、重复、循环、版本或人工锁定冲突，不能直接接受 |
| `ACCEPTED` | 人工原样接受并写入地图草稿，保留审计 |
| `EDITED_ACCEPTED` | 人工修改后接受，审计同时保存 AI 原建议和最终值 |
| `REJECTED` | 人工拒绝，不进入地图；保留原因可选 |
| `REVERTED` | 已接受变更后来被人工撤销；对应地图版本仍可追溯 |

### 9.4 目标与路线状态

- 目标：`ACTIVE`、`PAUSED`、`COMPLETED`、`ARCHIVED`。
- 路线：`CURRENT`、`STALE`、`SUPERSEDED`、`COMPLETED`。
- 地图版本变化、目标变化或人工状态变化可使路线成为 `STALE`；系统可建议重算，但必须在用户确认后才替换 `CURRENT` 路线。

## 10. 失败与异常流程

| 异常 | 用户可见反馈 | 系统行为与恢复 |
| --- | --- | --- |
| AI 未配置/被关闭 | “AI 不可用，人工功能不受影响”及人工创建入口 | 不发起网络请求，不生成占位数据；保留用户输入草稿 |
| AI 超时、限流或网络失败 | Provider、失败阶段、可重试提示，不暴露密钥 | 建议保持未提交；允许重试、复制输入或转人工；不得写正式地图 |
| AI 输出未通过结构校验 | 指出字段路径、缺失/未知字段 | 原始响应仅按安全策略用于诊断；拒绝创建可接受建议 |
| AI 边引用不存在节点/形成环 | 标记冲突项并显示关系与循环链 | 非冲突项仍需人工选择；冲突项修复前不可接受 |
| 手工创建环或重复边 | 在保存前说明“哪条边导致何种循环/重复” | 原子拒绝该变更，保留编辑表单和其他未保存修改 |
| 地图版本已变化 | 展示编辑基线、当前版本和差异 | 阻止静默覆盖；允许重新基于最新版、复制为新草稿或放弃 |
| 路线引用旧版本 | 标记 `STALE` 并列出新增、归档、关系变化 | 旧路线仍可查看；用户确认后才生成新路线 |
| 目标不可达或无节点可学 | 区分缺失前置、归档节点、地图错误和已全部掌握 | 给出可行动修复入口，不返回空白首页 |
| 导入格式、引用或 DAG 无效 | 返回文件级与项目级错误清单 | 先在临时区验证；整批不落正式数据，可下载错误报告 |
| 导出失败或磁盘空间不足 | 说明阶段、目标路径和可重试建议 | 不留下被标为成功的半成品；临时文件安全清理，原数据不变 |
| 证据附件丢失/不可读 | 记录仍可查看并标记附件缺失 | 不自动降低掌握等级；允许重新关联或删除引用 |
| 状态更新冲突 | 展示现值、用户待提交值和更新时间 | 用户明确合并或覆盖；覆盖产生审计记录 |

所有错误必须使用可理解语言并保留技术错误标识，不能只显示堆栈、空白页或“未知错误”。任何失败都不得让 AI 建议、导入数据或部分版本悄然成为正式内容。

## 11. 可访问性要求

MVP 以 WCAG 2.2 AA 为目标，并至少满足：

- 所有主要流程可仅用键盘完成；焦点顺序、可见焦点和跳过导航入口明确。
- 状态不只依赖颜色。节点状态同时提供文字、图标/形状和可读图例，色彩对比达到 AA。
- 图谱始终提供等价的大纲/关系表视图；屏幕阅读器用户无需操作画布即可查看前置、后续和阻塞。
- 节点、边、表单、差异和错误具有语义化标签；错误与具体字段关联，并在焦点移动后被宣读。
- 缩放到 200% 仍可完成核心流程；桌面与移动端不发生关键信息遮挡。移动端优先支持查看和学习，不承诺完整拖拽编辑。
- 拖拽不是唯一编辑方式；所有图谱关系可通过表单或键盘建立。
- 支持减少动态效果；不使用自动播放、闪烁或夸张动画。
- 日期、难度和掌握等级不只用数字，提供人类可读含义。
- 自动化可访问性检查之外，发布前必须对首页、目标路线、节点详情、AI 审核和导出执行人工键盘与屏幕阅读器烟测。

## 12. 隐私要求

- 默认本地存储、最少收集；MVP 不要求真实姓名、社交资料或无关身份信息。
- 外部 AI 默认关闭。首次启用必须说明 Provider、将发送的数据范围、目的和潜在跨境/第三方处理，并取得明确同意。
- 每次 AI 请求可预览将发送的目标或材料；用户可取消、脱敏或改用人工流程。未勾选的笔记、证据和附件不得被隐式附加。
- API 密钥只进入安全配置，不写入数据库导出、应用日志、审计详情或错误页面；日志对提示词中的潜在敏感内容做最小化和脱敏。
- AI Provider 的数据保留/训练政策由用户自行配置并在设置页提示；产品不作“绝不用于训练”的无依据承诺。
- 用户可查看、导出和删除自己的数据。删除分为可恢复归档与不可恢复清除，后者必须二次确认并说明影响。
- 审计日志记录必要元数据和差异，不额外复制完整敏感正文；保留期可配置，清理操作本身留摘要记录。
- 导出前可选择是否包含 AI 原始输出、审计详情和本地附件；默认不包含密钥、缓存、内部日志或其他用户数据。
- 对外网络请求仅发生在用户明确启用的 Provider 和当前操作范围内；禁用 AI 后不得后台探测或上传。

## 13. 数据可导出要求

### 13.1 MVP 格式与范围

提供一个带清单文件的 UTF-8 JSON 导出包；存在附件时可生成 ZIP。清单至少包含导出格式版本、应用版本、导出时间、对象计数和校验摘要。

可独立选择：

- `KnowledgeSpace`、全部 `KnowledgeMapVersion`、节点、节点版本、关系及来源。
- 学习目标、`LearningPath`、路线节点、地图/算法版本和推荐理由。
- `LearnerState`、学习记录、证据、资源引用、笔记和人工覆盖历史。
- `AISuggestion` 的原始结构化输出、审核结论和差异；默认可取消敏感原文。
- `AuditLog` 的可携带审计摘要。

### 13.2 可移植性与安全

- 节点使用稳定键，引用不得依赖当前数据库自增 ID；关系方向和类型必须显式。
- 导出模式有版本号和 JSON Schema；枚举、时间、时区、软删除和来源语义必须明确。
- 导入先做模式、唯一性、外键、重复边、DAG 和版本兼容性校验，再让用户预览将创建/合并的对象。
- 默认采用“创建新空间/新草稿”导入，不能静默覆盖现有地图或个人状态。
- 同一应用版本的完整导出必须能够在空数据库中往返导入，保持节点稳定键、关系、路线引用、个人状态和审核结论。
- 导出包永不包含 API 密钥、会话令牌、日志中的秘密或未选择的数据。

后续可提供面向阅读的 Markdown 和面向分析的 CSV，但它们不能替代完整 JSON 备份。

## 14. MVP 成功指标

指标用于验证导航闭环，不以时长、打卡或排行榜作为成功标准。除本地运行质量指标外，产品遥测必须用户选择加入；未加入时可通过可重复的可用性测试计算。

| 指标 | MVP 验证目标 |
| --- | --- |
| 核心闭环完成率 | 至少 80% 的受测用户能在无协助下完成“建图/选图 → 建目标 → 生成路线 → 更新状态 → 看到新下一步” |
| 首次可行动时间 | 使用“Python 基础”示例的受测用户，中位数 15 分钟内看到带理由的可学习节点 |
| 阻塞解释完整率 | 100% 的 `BLOCKED` 节点展示直接阻塞项、当前状态、最低要求和推荐先修；抽样用户至少 90% 能据此指出下一步 |
| 路线可追溯率 | 100% 路线记录地图版本、算法版本和每个推荐理由 |
| AI 人审完整性 | 100% 由 AI 发起的正式地图变更能追溯到人工审核动作；未经审核写入为 0 |
| 状态隔离完整性 | 更新个人状态不会改变地图或其他用户状态；改变路线不会删除状态历史 |
| 无 AI 可用性 | 不配置密钥时，五个端到端人工动作全部通过 |
| 数据可携带性 | 标准验收数据集完整导出并在空库往返导入，关键对象与引用 100% 一致 |
| 可访问核心流程 | 首页、路线、节点学习、AI 审核、导出均通过键盘操作；图谱信息在等价列表中 100% 可达 |
| 基线响应时间 | 本地标准数据集（不超过 1,000 节点、5,000 关系）下，路线/阻塞计算 P95 小于 2 秒；超限时有明确进度或错误 |

这些是发布前目标，不代表当前实现已经达到，更不代表已经验证真实学习效果。

## 15. 验收标准

MVP 只有在以下全部成立时才可验收：

1. 产品入口和导航明确表达通用框架构建定位，同时将 `LEARN` 作为第一等、默认且当前主要场景；支持按目标 intent 选择或调整 `LEARN`、`UNDERSTAND`、`DO`，未实现的扩展模板须诚实标注。
2. 能完成从创建空间到状态更新后重算下一步的 `LEARN` 最小闭环，且不依赖 AI。
3. `KnowledgeMap`、`LearningPath`、`LearnerState` 分表意、分生命周期、分写入入口；验收测试能证明三者不会互相代写。学习界面完整保留知识点、前置知识、掌握、复习、能力维度和学习记录，只在内部边界兼容旧字段/API/Schema。
4. `PREREQUISITE` 方向统一为“前置 → 被依赖”，新增环形硬依赖边被原子拒绝并返回完整循环链；非硬依赖关系可形成网络，不受该 DAG 规则误伤。
5. “下一步”首屏明确回答：目标/问题与当前位置、为何现在关注、下一步、缺口/阻塞，以及完成/理解/验证当前节点会改变什么。
6. 目标路线只包含目标祖先子图或人工明确补充节点，已达标节点不进入待学集合，所有推荐具备理由和算法/地图版本。
7. 每个阻塞节点都有直接和递归阻塞解释，不能只有“尚未解锁”。
8. 学习证据和状态更新可追溯；AI 评价不直接提升掌握等级；人工覆盖保留前后值与操作者。
9. AI 无法直接写正式地图；未校验、未审核、冲突或引用无效的建议均不能应用；接受、拒绝、编辑后接受、撤销可审计。
10. 地图发布与回滚版本化；新版本不会静默改写现有路线或个人状态。
11. 10 个核心页面具备定义的加载、空、成功、失败和无权限/不可用状态，不出现无恢复路径的空白页。
12. AI 关闭、Provider 失败、导入无效、导出失败、版本冲突时，数据保持一致并给出可行动恢复路径。
13. 完整 JSON 导出不含密钥，可在空库往返导入并保持稳定引用；危险覆盖必须预览和确认。
14. 外部 AI 发送前获得明示同意且可预览范围；禁用后无后台 AI 网络请求。
15. 核心流程通过键盘、非颜色状态识别和图谱等价列表验收。
16. [mvp-acceptance.md](./mvp-acceptance.md) 中所有 BLOCKER 场景通过，且报告实际执行结果；不得把未执行项写成已通过。
17. `semantic_profile` 只改变允许的目标级显示词；`template_id` 属于当前 intent，状态组、动作组和完整有序进度共同精确命中该版本化模板，并通过 NFKC/空白/casefold、`Cc`/`Cf`、固定字段和结构校验。任一规则失败时，AI 生成、旧 draft 读取和激活整组丢弃 Profile、回退 intent baseline，同时保留有效核心地图；canonical 六状态、四维分数、证据、解锁和路线结果完全一致。

## 产品约束与待验证假设

- MVP 先以 SQLite、关系表和运行时 NetworkX 支持本地单人规模；是否需要 PostgreSQL 或图数据库必须由真实瓶颈证明。
- 掌握模型是透明规则而非成熟认知诊断；用户信任是否来自“可解释 + 可覆盖 + 有证据”需要可用性测试验证。
- 路线偏好只做确定性排序。最短节点数不等于最佳学习路线，不以“最短”作为默认全局目标。
- 图谱编辑的桌面体验优先；移动端完整拖拽编辑延后，但浏览、学习、更新状态和查看阻塞必须可用。
