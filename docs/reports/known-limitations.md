# 已知限制

## 1. 使用边界

当前实现定位为本地单用户 MVP 和领域规则验证载体，不是可直接暴露到公网的多租户服务。自动化测试和浏览器烟测证明的是软件行为，不是安全认证、性能承诺或教育效果证明。

## 2. 限制清单

| 优先级 | 限制 | 当前影响 | 建议边界或缓解方式 |
| --- | --- | --- | --- |
| 高 | 本地单用户假设 | 数据模型虽包含用户标识，但主要流程围绕默认本地用户运行；没有验证多用户同时编辑和租户隔离 | 仅在可信本机使用；多人部署前补齐隔离与并发测试 |
| 高 | 无真实身份认证与授权 | API 不具备生产级登录、会话、角色权限、CSRF/速率限制等防护 | 不要直接暴露到互联网；生产试点前引入认证与资源级授权 |
| 中 | 地图版本是初始闭环 | 已支持不可变发布、版本比较和从历史版本创建新草稿，但尚无并发编辑控制、字段级语义 diff 或长期迁移兼容矩阵 | 可用于本地补偿式恢复；不要用它承担法规级版本治理 |
| 高 | 导入只重建地图 | 导出包已包含目标、路线、个人状态、证据、AI 审核结论和审计，但 JSON 导入目前只重建其中的地图 | 将其描述为“完整导出、地图导入”，不要描述为完整备份恢复；重要数据另行备份 SQLite 文件 |
| 高 | PostgreSQL 尚未实测 | 模型采用可移植类型和约束，但没有真实 PostgreSQL 迁移、事务、并发和查询行为证据 | 当前使用 SQLite；切换前执行独立集成测试矩阵 |
| 中 | 浏览器图谱的大规模可读性尚未建立基线 | 当前使用 NiceGUI 内置 ECharts，不再依赖 Cytoscape 公共 CDN；但大图的布局、标签密度和交互延迟仍缺少分层基准 | 继续保留路线列表与文本替代；建立多尺寸、多密度和低性能设备基准 |
| 中 | 规模与性能未建立基线 | NetworkX 在请求内构图，SQLite 面向本地规模；大图、密集依赖和多并发下的延迟与内存未知 | 在有负载证据前限制空间规模；先基准测试，再决定缓存、增量计算或图数据库 |
| 中 | AI Provider 未做全面生产验证 | Mock 路径可验证审核边界，但外部 Provider 的配额、超时、模型漂移、隐私条款和结构化输出稳定性依赖部署环境 | 默认可关闭 AI；外部调用前确认数据范围，并保留人工审核 |
| 中 | 可访问性仅有结构性设计，缺少完整人工审计 | 尚无屏幕阅读器、全键盘、缩放和减少动态效果的正式验收记录 | 关键任务保留列表/文本替代；试点前完成 WCAG 导向人工烟测 |
| 低 | 路线以确定性的主路线为主 | `ALTERNATIVE_TO` 可表达替代关系，但产品尚未提供成熟的多路线比较与权衡界面 | 把当前路线解释为建议顺序，不宣称是唯一最优路线 |

## 3. 不应作出的产品声明

当前版本不应宣称：

- 已证明能够提高学习效率、记忆保持率或考试成绩；
- 掌握等级是标准化测量结果；
- `NEEDS_REVIEW` 表示学习者已经遗忘；
- AI 生成的知识结构已经由权威来源验证；
- SQLite 测试结果自动等价于 PostgreSQL 生产兼容；
- 地图 JSON 导出可以被当前导入接口完整恢复为账户备份；
- 当前服务适合公网、多租户或高并发环境。

`mastery-rule-v1` 是透明、可测试的启发式规则。它适合生成导航提示和触发复习提醒，但需要真实使用数据与教育研究验证后，才能讨论学习成效。

## 4. 安全运行建议

- 默认绑定本机地址，在可信设备和可信网络中运行。
- 保持 AI 关闭，或只配置已完成隐私评估的 Provider；不要把密钥写入导出包、日志或仓库。
- 使用启动器或 `scripts/start.ps1` 迁移时会先创建一致性 SQLite 备份；仍应定期把数据目录和 `backups/` 复制到另一存储位置。
- 普通项目删除先进入回收站；永久删除前先导出或备份，并核对项目名称和影响范围。
- 把 AI 建议作为待审材料；接受前核对来源、关系方向、掌握要求和环形冲突。
- 大规模导入前使用副本数据库演练，并检查错误报告和节点/边计数。
