# 产品与工程审查报告（2026-08-12）

## 审查目标

本轮从用户数据生命周期、跨页面投影、AI 权限边界、并发与失败恢复、启动和迁移安全、隐私与本地产品体验六个方向审查 Frame。审查使用隔离 SQLite 数据库和独立端口；未迁移、归档或修改用户正在使用的数据库。

## 关键问题与修复

### P0：误删除与数据投影不一致

- 原“删除项目”实际上只归档目标，却以删除语义呈现；数据库仍保留路径和框架，用户无法判断项目究竟是否消失。
- 现在默认操作为“移到回收站”，首页、项目列表和下一步导航统一只投影活动项目。
- 回收站支持恢复；永久删除只允许对已归档项目执行，并要求精确输入项目名。删除按实体 ID 隔离，同名节点或其他项目不会被标题匹配误删。
- 路径、打卡、对话、建议及独占框架按明确所有权清理；共享框架仍被其他项目引用时保留。
- 普通 AI 对话同样支持归档、恢复和精确确认后的永久删除；正文、上下文、草稿和工具提案会清除，历史审计只保留不含内容的最小墓碑记录。

### P0：AI 越过人工确认修改项目

- 原工具调用可在模型返回后立即修改草稿，缺少逐项确认。
- 现在模型只能创建 `PENDING` 提案；界面展示提案，用户逐项应用或拒绝，应用时校验可见版本，避免旧页面覆盖新修改。
- 项目方案仍需“锁定方案”和“确认建立项目”两道人工作用边界。

### P0：启动位置、迁移与本地数据安全

- 原数据库路径依赖进程当前目录，从 IDE、快捷方式或其他目录启动可能静默创建第二个空数据库，表现为“项目全没了”。
- 数据根目录现在稳定解析；打包运行使用本地应用数据目录，源码运行也不再随调用目录漂移。
- 自动建表默认关闭，正式启动统一走 Alembic；迁移前执行 SQLite 完整性检查和一致性备份。
- 启动器先识别已有健康服务，再同步锁定依赖、备份、迁移和启动，且所有原生命令失败都会正确向上传递退出码。
- 新增路径序号唯一约束迁移，消除同一路径出现两个相同位置的结构歧义。

### P1：跨页面 AI、失败恢复与 UI 冻结

- 统一 AI 历史在当前页面原地切换，不再因会话类型跳转到新建页，也不再因页面作用域变化静默换线程。
- 普通问答、新建项目快捷指令和项目协作共用一套侧栏/全屏聊天工作区；项目草稿作为消息流中的产物卡片展示。
- 用户消息在供应商解析和网络请求前先持久化；配置、授权或上游失败都会保留用户消息并给出可重试状态。
- 隔离浏览器验收发现“新建项目”后台任务在没有 NiceGUI 客户端上下文时写 `localStorage` 会中断首条消息并永久显示“读取对话…”。现已把浏览器指针持久化降为非阻塞增强，并保证创建流程无论如何都会解除加载状态。

### P1：凭据、网络与本地接口边界

- Provider Profile 的创建、更新和删除现在同时保护数据库与系统密钥库；密钥库或数据库在写入中途失败会回滚并补偿恢复，不留下孤立密钥或失效配置。
- 被活动会话引用的 Profile 不能直接删除；归档会话会先解除引用。
- 远程 AI 接口必须使用 HTTPS，只有 localhost/loopback 允许明文 HTTP。
- 产品运行默认禁止通过任意 `X-User-ID` 切换本地用户；该能力仅在显式测试配置中开启。
- 本地服务限制可信 Host，数据库日志隐藏参数，避免对话、备注和目标进入 SQL 调试日志。

### P1：结构与状态同步

- 被活动或草稿路径引用的节点不能直接归档；API 返回受影响路径和项目数量，操作失败时节点、边、路径和审计均不改变。
- Dashboard、首页、项目列表和 AI 项目上下文统一过滤归档项目，按 ID 而不是标题关联。
- AI 项目上下文使用白名单和总量上限，优先当前目标、当前节点及一跳邻居，并记录省略数量，减少重复外发、超时和费用。
- 模型重复返回相同工具调用 ID 时，系统生成内部唯一提案 ID，避免下一轮因唯一约束回滚整条用户消息。

## 发布门禁

- Ruff：151 个文件格式检查通过，静态规则通过。
- Mypy：75 个源码文件无类型错误。
- Pytest：632 项通过；总覆盖率 64%。
- Alembic：隔离空库 `upgrade head -> check -> downgrade base -> upgrade head` 通过，未检测到 ORM/迁移漂移。
- 依赖：锁文件检查通过，`pip check` 通过，`pip-audit` 未发现已知漏洞。
- PowerShell：三个启动/质量脚本通过 AST 解析。
- 浏览器：隔离数据库实测项目归档后首页立即移除、回收站恢复后路线保持、永久删除必须精确标题确认；AI 新建项目指令在同一消息流生成草稿；1440×900 全屏与 390×844 侧栏均无横向溢出，输入区固定在底部。
- Git：提交前执行跟踪文件、用户数据库、环境文件、日志和密钥模式扫描。

## 仍需明确的产品边界

- 当前是回环地址上的本地单用户产品，不是具备登录、会话吊销和租户隔离的托管服务；对公网部署前必须接入真实认证与 CSRF/Origin 策略。
- PostgreSQL 尚未做真实集成和性能验收；SQLite 仍是本地产品的唯一已验证数据库。
- 导入能力仍以知识地图草稿为主，不等同于完整数据包恢复。
- 大型 ECharts 图谱的交互性能和可访问性仍需用真实规模数据验证。
- 本轮没有向真实外部 AI 供应商发送测试内容；远端配额、限流和模型差异需要单独验收。
- 测试存在一条 Starlette `TestClient`/httpx 弃用警告，应在依赖生态稳定后升级到推荐接口。
