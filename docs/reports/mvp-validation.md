# MVP 验证报告

## 1. 结论

Learning Navigator 当前已经形成一个可运行的本地单用户 MVP：用户可以创建知识空间，以节点和有向关系维护知识地图，选择目标，生成遵守硬前置约束的路线，更新个人掌握状态，并从首页获得可解释的下一步建议。AI 输出先进入建议队列，只有经过人工审核才会转为地图草稿内容。

本轮工程审计未发现阻断上述本地核心闭环的 `BLOCKER`。这不等同于产品已经满足生产部署、多人协作或学习成效验证要求；这些边界在 [known-limitations.md](./known-limitations.md) 中单列。

## 2. 验证范围与方法

本报告依据以下证据形成：

- 产品与架构契约：PRD、用户流程、MVP 验收标准、领域模型、关系语义和 `mastery-rule-v1`。
- 自动化检查：领域、应用、API、持久化、迁移与端到端测试。最终全量结果为 `129 passed`，分支覆盖率总计 `73%`。
- 浏览器验收：在真实 NiceGUI 页面中完成“空间 → 节点 → 边 → 目标 → 路线 → 首页”的核心流程。
- 视觉与运行时检查：Cytoscape 容器实测为 `1161 × 620`，生成 3 个 canvas，图谱不是仅有数据但不可见的空容器。
- 定向回归：修复后验证 dashboard 查询无写入副作用、`NEEDS_REVIEW` 的导航优先级，以及每条前置关系自己的 `required_mastery_level` 能逐项传入路线判断。

## 4. 本轮审计修正

### 4.1 dashboard 查询副作用

此前 dashboard 读取路径可能触发路线重算与持久化写入，使 GET 请求不再是稳定的只读投影。修正后首页从现有持久化路线构建展示数据；连续读取不会创建新路线或修改原路线。该行为已有集成回归覆盖。

### 4.2 `NEEDS_REVIEW` 导航优先级

到期复习必须在“已经达到要求”等级判断之前生效，否则过期节点会继续显示为 `MASTERED`。修正后：

- 到期节点显示 `NEEDS_REVIEW`；
- `NEEDS_REVIEW` 的硬前置会阻塞后继；
- dashboard 在同一路线中优先给出待复习节点，同时保持同状态节点的路线顺序。

这是一条复习提醒规则，不表示系统断言学习者已经遗忘。

### 4.3 逐项掌握要求

路线不再用一个全局默认值替代所有节点要求。每条硬 `PREREQUISITE` 关系的 `required_mastery_level` 会传入路线节点与阻塞判断；目标节点使用目标要求等级。定向测试覆盖不同前置边要求不同等级的情形。

### 4.4 图谱渲染

浏览器检查曾暴露 Cytoscape 在容器尚未就绪时初始化、以及包装元素宽度为零的问题。修正后等待容器存在并让包装元素占满可用宽度；实测图容器尺寸正常且创建 3 个 canvas。

### 4.5 数据安全与所有权

空间、节点、关系、目标和 AI 建议都在应用层按当前用户校验所有权；双用户回归验证另一用户不能读取或修改空间，也不能查看、审核或撤销他人的 AI 建议。`X-User-ID` 仍只是本地开发身份，不等价于真实认证。

AI 撤销会先检查节点是否被人工编辑、是否新增人工关系或学习记录；存在后续工作时整笔拒绝，不会把人工内容随 AI 节点一起归档。

### 4.6 地图版本与可移植性

地图可发布为不可变版本，发布后自动创建新草稿；历史版本恢复通过复制成新草稿完成。导出包含版本、路线项、学习状态、证据、AI 建议和审计；导入回归验证一次导入两张地图并保留学习目标与来源依据。个人历史的恢复仍不在当前导入范围内。

## 5. 质量门槛

交付前应从干净数据库再次执行以下门槛，并将最终输出附到发布记录，而不是手工回填本文中的临时数字：

1. 完整测试套件及覆盖率报告；
2. Ruff 静态检查；
3. mypy 严格类型检查；
4. Alembic `upgrade head`，并至少验证一次受控的 downgrade / upgrade 往返；本轮已在临时空库完成该往返与关键列断言；
5. FastAPI 健康检查和 NiceGUI 核心浏览器烟测；
6. 确认测试数据库、日志和临时服务进程已清理。

## 6. 验收解释

当前结论是“本地 MVP 的核心导航链路可运行、关键领域不变量有自动化保护、浏览器闭环可见”。以下内容不由本报告证明：

- 生产级身份认证、权限隔离和互联网暴露安全性；
- 完整数据包中个人路线、状态与审计历史的跨实例无损恢复；
- 地图版本在并发编辑、复杂字段语义差异和长期升级场景下的生产级可靠性；
- PostgreSQL 兼容性和大规模图性能；
- 真实用户的学习效果提升。

这些内容应在进入生产试点前按 [next-iteration.md](./next-iteration.md) 的优先级逐项关闭。
