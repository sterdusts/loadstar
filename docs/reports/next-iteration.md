# 下一轮迭代计划

## 1. 排序原则

优先级按“能否安全进入真实用户试点”排序。每个任务都附带可观察的完成条件；仅完成代码、没有测试或运行证据，不算关闭。

## 2. P0：进入受控试点前必须完成

### P0-1 加固地图版本发布与回滚闭环

当前已实现草稿发布、结构差异、历史查看和“从历史版本创建新草稿”的补偿式回滚；下一轮补齐并发控制、字段级语义差异和跨迁移版本验证。

验收条件：

- 并发发布或恢复会产生可解释冲突，不会静默覆盖；
- 发布前检查引用、重复边、硬前置 DAG 和人工锁定字段；
- 旧路线继续引用原地图版本，个人状态不因回滚被静默改变；
- 发布、失败发布和回滚均有集成测试与审计记录。

### P0-2 完整数据包导入导出

把当前“地图导入”扩展为有明确 schema 版本的完整数据包，覆盖目标、路线、个人状态、证据、建议审核结论和审计引用。

验收条件：

- 从标准夹具导出，在空数据库导入后，稳定标识、对象计数和关键引用逐项一致；
- 未知引用、重复边、环形前置或不支持的 schema 版本会整批失败且数据库无部分写入；
- 默认创建新空间/草稿，覆盖现有数据必须单独预览和确认；
- 密钥、环境变量和敏感日志不进入导出包。

### P0-3 认证、授权与部署安全边界

确定产品是“仅本机应用”还是“可远程访问服务”。若允许远程访问，加入真实认证、会话安全和资源级授权。

验收条件：

- 未认证请求不能访问受保护 API；
- 两个测试用户不能读取或修改对方的空间、状态、证据和建议；
- 地图编辑、AI 审核、数据导出和管理操作分别有权限测试；
- 部署文档明确监听地址、反向代理、秘密管理、CSRF/CORS 与速率限制策略。

### P0-4 固化离线前端依赖

为当前 NiceGUI/ECharts 图谱建立大图布局、标签密度、键盘导航和低性能设备基准；保留列表与文本作为稳定替代视图。

验收条件：

- 断网环境可打开图谱并完成节点、边和路线查看；
- 浏览器断言容器尺寸大于零、存在 canvas，并能从图切换到等价列表；
- 依赖版本、许可证和升级步骤记录在仓库中。

### P0-5 可重复的交付质量门槛

将测试、覆盖率、Ruff、mypy、Alembic 往返和启动烟测固化为单一 CI/本地命令。

验收条件：

- 干净检出可通过一条有文档的命令安装并运行全部门槛；
- 任一门槛失败时返回非零状态；
- 最终测试数与覆盖率由流水线产物生成，不靠手工维护文档数字；
- 临时数据库、日志和后台服务在成功或失败后都能清理。

## 3. P1：提高可信度与可用性

### P1-1 PostgreSQL 兼容与并发验证

在真实 PostgreSQL 上执行迁移、仓储和并发测试，验证事务隔离、唯一约束及乐观锁语义。

验收条件：SQLite 与 PostgreSQL 使用同一套领域用例；空库迁移和升级路径通过；并发更新产生可理解的冲突而不是静默覆盖；结果进入 CI 服务矩阵。

### P1-2 完整可访问性验收

对首页、地图列表/图谱、节点详情、目标路线、AI 审核和设置页执行键盘与屏幕阅读器烟测。

验收条件：核心闭环不依赖鼠标；焦点顺序稳定；错误和动态状态可被宣读；200% 缩放和窄屏无关键操作丢失；图谱有等价文本列表。

### P1-3 多路线比较

利用软前置和 `ALTERNATIVE_TO` 生成有限数量、可解释的路线变体，显示时间、难度与偏好差异。

验收条件：任何变体都不得绕过硬前置；同一输入和版本产生稳定结果；用户能查看排序理由并选择路线；测试覆盖菱形图、多根图和无可行动节点。

### P1-4 AI 生产防护与可追溯性

补齐外部 Provider 的超时、重试上限、隐私确认、结构化失败恢复、来源展示和批量审核安全策略。

验收条件：Provider 不可用时人工流程仍完整；无效 JSON 不落正式数据；每项接受结果可追溯到 provider、model、prompt 版本、来源和审核人；批量操作原子失败或逐项明确报告。

### P1-5 学习证据与状态重建

支持撤回证据后按时间顺序重放 `mastery-rule-v1`，并为人工覆盖保留不可混淆的审计语义。

验收条件：同一证据序列重放得到确定结果；撤回不会硬删除历史；人工覆盖原因必填；规则升级使用新版本标识并提供 dry-run 差异。

## 4. P2：有真实使用数据后评估

### P2-1 大图性能与增量计算

建立分层基准数据集，测量构图、目标子图、拓扑排序、阻塞解释、dashboard 和 ECharts 渲染。

验收条件：报告至少覆盖稀疏/密集、深链/宽图和多目标场景；记录 P50/P95 延迟与峰值内存；只有指标超出预算后才引入缓存、增量计算或图数据库。

### P2-2 学习成效研究

设计经伦理与隐私审查的试点，对导航建议是否改善完成率、复习及时性和理解保持进行验证。

验收条件：预先定义样本、对照、指标与退出条件；把产品参与度和学习效果分开；允许导出和删除参与者数据；结果无论正负都记录。

### P2-3 协作式地图治理

在单用户模型稳定后再引入编辑者、审核者和学习者之间的协作、评论、提案与冲突解决。

验收条件：角色权限矩阵可自动测试；所有正式变更可定位到提案、审核与版本；并发冲突不静默覆盖；学习者私有状态不暴露给地图编辑者。

### P2-4 存储架构复评

根据 PostgreSQL 与 NetworkX 的真实性能证据决定是否需要图数据库或专用图计算服务。

验收条件：形成包含当前瓶颈、目标规模、迁移成本、事务/审计需求和回退方案的 ADR；没有量化收益时保持现有关系模型。

## 5. 建议执行顺序

先完成 P0-1 与 P0-2，建立可信的版本和恢复边界；并行推进 P0-3 与 P0-4，关闭部署和离线运行风险；最后用 P0-5 把所有门槛固化。P1 在受控试点准备期推进，P2 只在获得真实使用数据后启动，避免提前为未出现的规模问题增加系统复杂度。
